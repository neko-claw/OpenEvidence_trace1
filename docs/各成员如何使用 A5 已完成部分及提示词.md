# 各成员如何使用 A5 已完成部分及提示词

> 仓库：`https://github.com/neko-claw/OpenEvidence_trace1`
> A5 当前版本：`0.3.0`
> 本文只说明每位成员需要使用 A5 的哪一部分、如何使用，以及可以直接交给执行助手的提示词。

## 使用 A5 前的共同约束

当前真实入口是：

```python
from a5.api import answer

run = answer(question, workflow=configured_workflow)
payload = run.model_dump(mode="json")
```

所有成员给执行助手的提示词都应要求：

- 保持 `answer(question, workflow=...)->AgentRun` 兼容。
- 不重写 `a5/agent/workflow.py` 的有限状态机。
- 正式能力通过 Protocol/Adapter 接入。
- `build_demo_workflow()`、Mock Evidence 和 fixture 只用于离线测试。
- UNKNOWN 安全或验证数据不能变成 ALLOW/SUPPORTED。
- 不编造 PMID、DOI、NCT、URL、指南编号、score、level、date 或 span。
- 修改后先跑相关测试；准备交付时运行 `pixi run test` 和 `pixi run demo`。

## A1：产品与医学场景

### 需要使用的 A5 部分

- `a5/ports/safety_policy.py`
- `a5/domain/models.py` 中的 `Question`、`SafetyAssessment`
- `config/skills.yaml`
- Gate0、Gate2、Gate5、Gate6
- PASS/WARN/REFUSE 和“拒答前不调用工具”测试

### 怎么使用

A1 把正式 question type、安全范围、拒答 reason code、终止规则和 rubric 交给 A5。执行助手应新增 A1-backed `SafetyPolicy` Adapter，并把题型规则写入版本化配置。

A1 还要用 A5 已有测试案例复核：

- 证据充分、关键 Claim 全支持：PASS
- 次要 Claim 不足：WARN
- 关键 Claim 不足或非法引用：REFUSE
- 安全信息无法确认：UNKNOWN -> REFUSE

中硬编码医学规则；无法判断必须返回 UNKNOWN。验证 UNKNOWN/DENY 在检索前
REFUSE，ALLOW 才继续。补充范围外、个体化高风险请求和 A1 rubric 案例测试。
