# A1–A5 兼容性审查与 A5 实施报告

日期：2026-08-12
规范基线：`docs/OpenEvidence_MVP_赛道1与赛道3实施规划.md`；用户提供副本与仓库副本内容一致，仅换行编码不同。
性质：工程契约与离线控制流验收，不是医学效果评测。

## 1. 结论

A5 的有限状态机和 `answer(...)->AgentRun` 保持稳定。本轮新增显式 Gate1、检索分数语义、真实 A2/A3/A4 branch contract Adapter、A2→A3 normalizer、完整 Span locator/hash 校验、可复现 as-of date，以及数值/单位确定性检查。

跨分支整体仍为 **INTEGRATION PENDING**：A1–A4 尚未全部进入 main；A3 的真实 BGE-M3 和 A4 的 CrossEncoder/rerank 消融没有达到规划要求的真实 dev 验证。A5 对这些能力默认关闭并 fail closed，不以 mock 或“模型可加载”冒充验证完成。

## 3. Rerank 风险处理

规划要求：R0=BM25+Vector+RRF，R1=R0+特征 rerank+MMR，R2=R1+CrossEncoder，R3=R2+Claim-Evidence gate，且 B/C 条件复用同一初始候选池。

当前 A4 风险包括 R0 仍构造 FeatureReranker、R2 参数未实际进入 condition、R3 在门禁全删后恢复候选、CrossEncoder raw logit 与 `[0,1]` 特征分直接混合，以及消融缺 R2。A5 不修写 A4 算法，而采用以下隔离：

1. `EvidenceRecord` 明确 `retrieval_score_kind/scope/calibrated`；
2. A4 `rerank_score` 映射为 `RANKING + QUERY_LOCAL + calibrated=false`；
3. Gate2 只接受 `QUALITY + CROSS_QUERY + calibrated=true`；
4. raw ranking score 仍保留为 `top_ranking_score` 供 Trace 诊断，但不能满足 `min_top_score`；
5. 未验证 CrossEncoder 默认 capability disabled；若 A4 声明相关 feature，Adapter 拒绝生产接入。

这符合 [RRF 原论文](https://research.google/pubs/reciprocal-rank-fusion-outperforms-condorcet-and-individual-rank-learning-methods/)“按名次融合”的定位，也符合 [SentenceTransformers CrossEncoder 官方文档](https://www.sbert.net/docs/package_reference/cross_encoder/model.html)：输出与 activation 取决于模型配置，raw logit 不能自动解释为跨查询质量概率。

## 4. BGE-M3 风险处理

BGE-M3 本身是支持 dense/sparse/multi-vector 的多语言检索模型，见[论文](https://arxiv.org/abs/2402.03216)与[官方仓库](https://github.com/FlagOpen/FlagEmbedding)。这只能证明模型能力与实现来源，不能证明它适合本项目中文医疗 dev 集。

本轮策略：

- A3 是 Embedding 唯一所有者；A4 不再拥有第二套模型加载路径；
- `config/integrations.yaml` 将 BGE-M3 标为 disabled/PENDING；
- 启用前必须有同一冻结候选池的 Recall@50、延迟、维度和重建一致性；
- 模型、revision、provider、source kind、index version 必须进入 runtime snapshot；
- 未验证模型出现在生产 A4 chunk 时，A5 Adapter 拒绝接入；Mock smoke 不升级为正式质量证据。

## 5. Gate 对规划的映射

| 规划 Gate | A5 实现 |
|---|---|
| Gate0 | A1 SafetyPolicy Port；ALLOW 才继续，DENY/UNKNOWN 拒答 |
| Gate1 | `EvidenceIntegrityGate`；mock 模式显式；production provenance marker/字段；tombstone/mismatch 拒绝 |
| Gate2 | 候选数、校准质量分、来源覆盖/多样性、证据等级、时效、冲突；预算内纠错重试 |
| Gate3 | `ClaimSplitter` 原子化主张；复合主张不能整体放行 |
| Gate4 | Evidence/Span 白名单绑定；模型不得生成外部引用标识 |
| Gate5 | Evidence ID、真实 Span、PICO、时间、冲突、文本支持扩展点、数值/单位、不确定性 |
| Gate6 | critical claim、非法引用、冲突、UNKNOWN/HIGH uncertainty 与上游 Gate 共同聚合 PASS/WARN/REFUSE |

Gate2 的“先评价检索质量再决定继续/纠正/拒答”借鉴 [CRAG](https://arxiv.org/abs/2401.15884)；Atomic Claim 借鉴 [FActScore](https://arxiv.org/abs/2305.14251)；引用有效性、覆盖与相邻支持拆分借鉴 [ALCE](https://arxiv.org/abs/2305.14627)；检索错误与生成错误的原因码分离借鉴 [RAGChecker](https://github.com/amazon-science/RAGChecker)。只采用控制模式，未复制外部实现。

## 6. Adapter 数据流

```text
A1 Question/Safety
  -> A1QuestionAdapter / A1SafetyPolicyAdapter
  -> Question + Gate0

A2 Evidence v1 / MCP ToolResponse
  -> A2MCPRetriever
  -> A2ToA3EvidenceAdapter
  -> A3 Evidence -> Chunk -> real Span
  -> A4 search/rank result
  -> A4RAGRetriever
  -> A5 EvidenceRecord compatibility view
  -> Gate1 -> Gate2 -> Claim -> Gate5 -> Gate6
```

缺失数据一律为 null/UNKNOWN。A5 不实现 PubMed/ClinicalTrials/Guideline 采集，不实现 Embedding、BM25、Vector、RRF、rerank、MMR，也不把 exact span check 宣称为医学语义验证。

## 7. 契约测试证据

新增/更新测试覆盖：

- A1 Question/Safety contract 与检索前 fail-closed；
- A2 Evidence v1 字段、MCP envelope、tool route、A2→A3 normalizer；
- A3 chunk/span hash、offset、归属、无合成 span；
- A4 Evidence 聚合、冲突、版本、真实 Span Provider；
- 未验证 BGE-M3/CrossEncoder capability 阻断；
- Gate1 mock/production 状态；
- 未校准 query-local score 不得成为 Gate2 quality score；
- Gate5 数值不一致即使语义扩展点返回支持也不能放行；
- FSM Trace 显式包含 Gate1。

当前中间回归：`pixi run test` 为 **73 passed**。最终 demo 与完整测试结果以 `docs/merge_readiness_report.md` 为准。
